# Database Specification & Migration Guide

## 1. Relational Tables Overview

The ScholarPilot relational data layer maintains three core tables:
1. `schemes` — Authoritative scholarship records crawled and verified from official portals.
2. `profile` — Student demographic, academic, and socio-economic facts.
3. `score` — The matching and recommendation results generated by the AI/ML service.

---

## 2. Table Schemas

### 2.1 `schemes` Table
| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | VARCHAR(64) | PRIMARY KEY | Unique scheme slug/identifier |
| `title` | VARCHAR(255) | NOT NULL, INDEX | Verified scheme title |
| `provider` | VARCHAR(255) | NOT NULL | Official ministry, department, or trust |
| `scope` | VARCHAR(32) | NOT NULL | `CENTRAL`, `STATE`, or `PRIVATE` |
| `eligible_states` | JSON / JSONB | NOT NULL, DEFAULT '[]' | List of state codes (e.g. `["BR", "HR"]`) |
| `education_levels` | JSON / JSONB | NOT NULL, DEFAULT '[]' | e.g. `["CLASS_12", "UG"]` |
| `courses` | JSON / JSONB | NOT NULL, DEFAULT '[]' | e.g. `["BTECH", "MBBS"]` |
| `category_rules` | JSON / JSONB | NOT NULL, DEFAULT '[]' | e.g. `["SC", "ST", "OBC", "GEN"]` |
| `income_limit_inr` | BIGINT | NULLABLE | Maximum annual family income in INR |
| `minimum_marks_percent` | FLOAT | NULLABLE | Minimum academic qualifying percentage |
| `award_amount_inr` | BIGINT | NULLABLE | Benefit amount in INR |
| `deadline` | VARCHAR(32) | NULLABLE | ISO date string (`YYYY-MM-DD`) |
| `required_documents` | JSON / JSONB | NOT NULL, DEFAULT '[]' | List of required application documents |
| `official_url` | VARCHAR(512) | NULLABLE | Official application portal URL |
| `source_checked_at` | VARCHAR(64) | NULLABLE | ISO timestamp of source verification |
| `verification_status` | VARCHAR(32) | NOT NULL, DEFAULT 'VERIFIED' | `VERIFIED` or `NEEDS_REVIEW` |
| `unknown_fields` | JSON / JSONB | NOT NULL, DEFAULT '[]' | Unverified or missing scheme facts |
| `created_at` | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | Row creation timestamp |
| `updated_at` | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | Row modification timestamp |

### 2.2 `profile` Table
| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | VARCHAR(64) | PRIMARY KEY | Unique profile ID |
| `user_id` | VARCHAR(64) | NOT NULL, INDEX | Foreign key to auth user (strictly decoupled) |
| `state` | VARCHAR(32) | NULLABLE | Student domicile state code (e.g. `BR`) |
| `education_level` | VARCHAR(32) | NULLABLE | e.g. `UG`, `CLASS_12` |
| `course` | VARCHAR(64) | NULLABLE | e.g. `BTECH`, `MBBS` |
| `category` | VARCHAR(32) | NULLABLE | e.g. `SC`, `ST`, `OBC`, `GEN` |
| `annual_family_income_inr` | BIGINT | NULLABLE | Annual family income in INR |
| `marks_percent` | FLOAT | NULLABLE | Previous examination percentage |
| `disability` | BOOLEAN | NOT NULL, DEFAULT FALSE | Whether student has verified disability |
| `gender` | VARCHAR(32) | NOT NULL, DEFAULT 'NOT_PROVIDED' | Student gender |
| `consent_to_process_profile`| BOOLEAN | NOT NULL, DEFAULT TRUE | DPDP Act compliant user consent |
| `created_at` | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | Row creation timestamp |
| `updated_at` | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | Row modification timestamp |

### 2.3 The New `score` Table
Persists matching results with guaranteed idempotency and auditability:
| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | VARCHAR(64) | PRIMARY KEY | Unique record ID (`scr_...`) |
| `profile_id` | VARCHAR(64) | NOT NULL, FK -> profile(id) | Target student profile ID |
| `scheme_id` | VARCHAR(64) | NOT NULL, FK -> schemes(id) | Recommended scholarship ID |
| `match_score` | FLOAT | NOT NULL | Normalized transparent score (0.00 to 100.00) |
| `eligibility_status` | VARCHAR(32) | NOT NULL | `ELIGIBLE`, `NOT_ELIGIBLE`, or `NEEDS_REVIEW` |
| `reasons` | JSON / JSONB | NOT NULL | Full rule evaluations, evidence, and scores |
| `missing_fields` | JSON / JSONB | NOT NULL, DEFAULT '[]' | List of unverified or missing facts |
| `created_at` | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | Matching run creation timestamp |
| `updated_at` | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | Last match recompute timestamp |

* **Constraints & Indexes:**
  * `UNIQUE (profile_id, scheme_id)` — Enforces exactly one current matching result per student–scheme pair.
  * `INDEX idx_score_lookup (profile_id, eligibility_status)` — Fast retrieval for filtered tabs.
  * `INDEX idx_score_ranking (profile_id, match_score DESC)` — Optimized sorting by score.

## 3. SQL DDL for PostgreSQL Migration

```sql
-- Create 'score' table
CREATE TABLE IF NOT EXISTS score (
    id VARCHAR(64) PRIMARY KEY,
    profile_id VARCHAR(64) NOT NULL REFERENCES profile(id) ON DELETE CASCADE,
    scheme_id VARCHAR(64) NOT NULL REFERENCES schemes(id) ON DELETE CASCADE,
    match_score NUMERIC(5, 2) NOT NULL,
    eligibility_status VARCHAR(32) NOT NULL,
    reasons JSONB NOT NULL DEFAULT '{}'::jsonb,
    missing_fields JSONB NOT NULL DEFAULT '[]'::jsonb,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uq_score_profile_scheme UNIQUE (profile_id, scheme_id)
);

CREATE INDEX IF NOT EXISTS idx_score_lookup ON score(profile_id, eligibility_status);
CREATE INDEX IF NOT EXISTS idx_score_ranking ON score(profile_id, match_score DESC);
```
